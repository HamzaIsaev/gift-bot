# Gift Bot

Бот для торговли NFT-подарками Telegram на Portals, Tonnel и MRKT.
Он ищет лоты дешевле рынка, перепродаёт их и отдельно сигналит о межплощадочном арбитраже.

По умолчанию бот работает в режиме наблюдения: ничего не покупает, а записывает виртуальные сделки.
Боевой режим с реальными сделками включается вручную, с подтверждением.

## Как работает

1. Каждые `POLL_INTERVAL_SEC` секунд бот забирает с каждой площадки новые лоты и последние продажи.
2. Рыночная цена модели считается как среднее floor (самого дешёвого другого лота) и медианы продаж за `SALES_WINDOW_DAYS` дней.
   Если продаж мало, берётся только floor.
3. Расчёт сделки: затраты = цена × (1 + комиссия покупателя) + сетевой сбор.
   Выставление идёт чуть ниже рынка, но не выше floor.
   На руки = цена выставления × (1 − комиссия продавца) − сетевой сбор.
4. Сигнал на покупку появляется, если прибыль ≥ порога (`MIN_PROFIT_PCT`, по умолчанию 12%).
5. **Адаптивность** (`ADAPTIVE=true`):
   - для неликвидных моделей порог выше (+8%), для ликвидных ниже (−2%);
   - для волатильных моделей порог выше;
   - модели, на которых недавно был убыток, пропускаются на `LOSER_COOLDOWN_DAYS` дней;
   - если сегодня уже потеряно больше половины дневного лимита, порог выше (+3%);
   - если рынок ушёл ниже нашей цены, цена сразу подтягивается под floor.
6. Если подарок не продаётся `REPRICE_AFTER_HOURS` часов, цена снижается на `REPRICE_STEP_PCT`%,
   но **никогда не ниже безубыточности** (цена покупки + комиссии).
7. Арбитраж: тот же подарок дешевле на одной площадке и дороже на другой.
   С учётом `TRANSFER_COST_TON` это только сигнал, без автосделки.
8. Виртуальная продажа засчитывается, когда на площадке проходит продажа той же модели не дешевле нашей цены.

## Торговая математика v2

Бот покупает только фундаментально недооценённые и ликвидные подарки. Данные берутся со всех площадок сразу, цены приводятся к TON «на руки».

- **Справедливая цена (fair):**
  - медиана продаж за 7 и 30 дней, свежие продажи весят больше;
  - выбросы отсекаются по MAD;
  - вместо 1-го лота берётся глубина стакана (2–3-й лот);
  - дисконт, если продаж мало или тренд падает (EMA 3д vs 14д).
- **Ликвидность** считается по всем площадкам: продажи за 24ч и 7д, оборот, ожидаемое время продажи, спред.
- **Фундаментальность 0–100** с разбивкой по факторам: редкость модели/фона/символа, тираж, число улучшенных, возраст, стабильность цены.
- **Новые коллекции:** первые 3 дня бот их не покупает, до 14 дней — повышенный порог, меньший размер позиции и дополнительный дисконт.
- **Решение о покупке:**
  - EV = (продажа − покупка)·P(продажи) − риск;
  - покупка, если EV% ≥ порога, score ≥ MIN_SCORE и пройдены фильтры ликвидности;
  - размер позиции — дробный Келли (×0.25) с лимитом концентрации на коллекцию.
- **Продажа:** шаг снижения цены зависит от ликвидности. Если fair упал и тренд вниз, бот присылает сигнал на выход.
- **Прозрачность:**
  - у каждого решения записана причина;
  - в панели видны колонки fair, score, продаж/7д, EV;
  - в `/report` видно, сколько сделок отсеяно и почему.
- **Включение:** v2 работает только в режиме наблюдения (`STRATEGY_V2_LIVE=false`). Для боевого режима сначала сравните логики бэктестом:
  `docker compose exec gift-bot python scripts/backtest.py --days 14`

## Боевой режим

Включается кнопкой «💰 Боевой» в `/mode` или в админ-панели, в обоих случаях с подтверждением.

Как бот торгует:
- покупает лот и тут же выставляет его на той же площадке с внутреннего баланса площадки;
- баланс пополняется вручную: площадка → Deposit → кошелёк. Сид-фраза боту не нужна;
- перед каждой покупкой проверяет баланс и лимиты;
- торговые запросы **не повторяются**: защита от двойной покупки;
- если подарок нельзя выставить сразу (блокировка после покупки), выставляет, когда станет можно;
- продажа фиксируется, когда подарка дважды подряд нет в нашем инвентаре;
- арбитраж между площадками остаётся сигналом.

Перед первым запуском:
- сверьте комиссии в `.env`;
- на первые дни поставьте маленькие лимиты, например `/limits max_trade 5`.

## Лимиты (обязательные)

- `max_trade`: максимальная сумма одной сделки.
- `max_daily_loss`: максимальный дневной убыток. При достижении бот прекращает покупки до конца дня и пишет вам.
- `max_positions`: максимум подарков на балансе одновременно.
- `/stop`: мгновенно останавливает всё, включая переоценку. Состояние сохраняется после перезапуска.

## Команды Telegram-бота

Меню содержит кнопки «Статус», «Режим», «Лимиты», «Стоп».

| Команда | Что делает |
|---|---|
| `/status` | баланс, открытые позиции, прибыль за день и за всё время |
| `/mode` | переключение режима и снятие `/stop` |
| `/limits` | просмотр лимитов; изменение: `/limits max_trade 25` |
| `/report` | отчёт за неделю |
| `/stop` | аварийная остановка |

Еженедельный отчёт приходит по понедельникам в 9:00 (`REPORT_WEEKDAY`, `REPORT_HOUR`).

## Вход без api_id (если my.telegram.org недоступен)

**Вход по номеру телефона (на сервере):** отправьте боту `/login`. Бот спросит номер второго аккаунта, затем код из Telegram и облачный пароль, если он есть. Номер, код и пароль бот сразу удаляет из чата.
Код вводите **с пробелами** (`1 2 3 4 5`): иначе Telegram аннулирует его как «пересланный». Отмена: `/cancel`.

**Вход по QR-коду:** Если оставить `TG_API_ID` пустым, `start.command` откроет окно браузера с Telegram Web.
Отсканируйте QR вторым аккаунтом: Telegram → Настройки → Устройства → Подключить устройство.
Дальше программа сама зайдёт в Portals, Tonnel и MRKT и заберёт данные входа.
Потом бот сам обновляет их в фоне каждые 6 часов. Войти заново: `bash start.command --relogin`.

Запасной вариант — вручную:

Если оставить `TG_API_ID` пустым, бот будет входить на площадки вручную:
1. Откройте web.telegram.org/k в Chrome и откройте мини-приложение площадки.
2. Нажмите Cmd+Option+J, в списке `top` выберите фрейм площадки.
3. Выполните `copy(Telegram.WebApp.initData)`.
4. Отправьте боту `/auth portals <вставить>`. Для Tonnel и MRKT — то же самое со словами `tonnel` и `mrkt`.

Данные можно вставить и в админ-панели. Со временем они устаревают, тогда бот напомнит их обновить.

## Мини-приложение в Telegram

На сервере админ-панель открывается прямо в Telegram: кнопка **«APP»** слева от поля ввода в чате с ботом, или команда `/app`.
- Вход без пароля: Telegram подписывает данные, бот проверяет подпись и пускает только `ADMIN_IDS`.
- https даёт Caddy с бесплатным сертификатом для адреса `<ip-с-дефисами>.sslip.io`, покупать домен не нужно. Свой домен можно указать в `PANEL_DOMAIN`.
- На сервере должны быть открыты порты 80 и 443.

## Админ-панель

Пока бот работает, админ-панель открыта по адресу http://localhost:8080. На Mac её открывает `start.command`.

Что есть в панели:
- баланс и прибыль за день, неделю и всё время;
- график прибыли по дням;
- лимиты, которые можно менять прямо в панели;
- открытые позиции, история сделок и все сигналы;
- кнопки «Режим», «Стоп» и «Продолжить».

На сервере задайте `PANEL_HOST=0.0.0.0` и обязательно `PANEL_PASSWORD`, иначе панель не запустится.

## Установка

### Что понадобится
- **Сервер:** VPS с 1 vCPU и 1 GB RAM, Ubuntu 22.04/24.04, Docker. Лучше в Европе (Нидерланды или Германия).
- **Управляющий бот:** создайте у [@BotFather](https://t.me/BotFather) и получите `BOT_TOKEN`.
- **Отдельный Telegram-аккаунт** для входа на площадки:
  - получите `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org) в разделе API development tools;
  - откройте с этого аккаунта Portals, Tonnel и MRKT хотя бы один раз (чтобы принять условия).

### Быстрый старт на Mac
1. Скачайте код (Code → Download ZIP) и распакуйте.
2. Откройте файл `start.command`. Если macOS не даёт его открыть, нажмите правой кнопкой → «Открыть».
3. Ответьте на вопросы. При первом запуске скрипт сам установит зависимости, создаст `.env` и выполнит вход в Telegram, а затем запустит бота.

### Перенос на сервер (24/7)
1. Арендуйте VPS: Ubuntu 24.04, **2 ГБ RAM**, 20+ ГБ диска, лучше Нидерланды или Германия.
2. **Остановите бота на Mac** (Ctrl + C): два бота с одним токеном мешают друг другу.
3. Скопируйте папку бота на сервер (с Mac):
   `rsync -a --exclude .venv --exclude data/tg_web_profile ~/gift-bot/ root@IP_СЕРВЕРА:gift-bot/`
4. Зайдите на сервер и запустите установку:
   `ssh root@IP_СЕРВЕРА` → `bash gift-bot/scripts/server_setup.sh`
5. В Telegram отправьте боту `/qr` и отсканируйте присланный QR вторым аккаунтом.
6. Админ-панель: `http://IP_СЕРВЕРА:8080`, пароль задаётся на шаге 4.

### Шаги (сервер, вручную)
```bash
git clone https://github.com/HamzaIsaev/gift-bot.git && cd gift-bot
cp .env.example .env            # заполнить BOT_TOKEN, ADMIN_IDS, TG_API_ID, TG_API_HASH

# одноразовый вход в Telegram-аккаунт -> TG_SESSION_STRING
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python scripts/login.py         # вставить выданную строку в .env

docker compose up -d --build    # запуск 24/7 с автоперезапуском
docker compose logs -f          # логи
```

## Безопасность

- Все ключи и сессия хранятся только в `.env`, а `.env` добавлен в `.gitignore`.
- Логи автоматически вычищают токены, сессию и initData.
- `TG_SESSION_STRING` даёт полный доступ к Telegram-аккаунту. Никому её не передавайте.
- Сид-фраза кошелька в режиме наблюдения не нужна.

## Данные для анализа

Всё пишется в SQLite (`data/gift_bot.sqlite3`):
- `sales`: продажи на площадках;
- `signals`: каждый интересный лот с расчётом и решением (`buy`, `skip` с причиной, `signal` для арбитража);
- `positions`: виртуальные и реальные сделки с прибылью;
- `settings`: режим, лимиты и `/stop`.

## Важно

- API площадок **неофициальные**. Они могут измениться, а автоматизация может нарушать правила площадок.
- **Комиссии в `.env` нужно сверить** с мини-приложениями перед боевым режимом.
